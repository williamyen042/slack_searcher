Architecture
Browser (Next.js chat UI · localhost:3000) └─ POST /api/chat (streaming SSE) └─ LLM host (reasons only over tool output) └─ MCP protocol (HTTP/SSE) └─ Python MCP Server (FastMCP · localhost:8002) ├─ search_slack() → Slack API + OpenAI embed + cosine rank ├─ get_thread() → conversations.replies ├─ list_channels() → channel discovery └─ get_reactions() → emoji reaction sentiment └─ Slack Workspace (real messages, real links)
RAG pipeline — per query
1

Index (on a timer)

python index.py pulls only messages newer than the stored per-channel cursor, chunks them, embeds what changed, and persists to SQLite. Re-running on an unchanged corpus costs zero embedding calls.

2

Chunk

Each message split into overlapping token windows (350 tok, 60 overlap). Natural boundaries respected — paragraphs → sentences → words. full_text always preserved on every chunk.

3

Embed

At index time, batched calls of 256 chunks — only those whose text_hash changed. Model: text-embedding-3-small, namespaced in the primary key so vectors from different models can never mix.

4

Rank — _rank_chunks()

Per query: embed the query only, then cosine against the stored matrix. Best chunk per original message (dedup). Sort descending. Return top-k as {text, author, channel, ts, permalink, score}.

5

Cite

The system prompt requires every factual claim to be followed by [source](permalink). If tools return nothing, the assistant says so. No fabrication path exists.

Phase 4 — Measure and decide

Run eval in all three modes · comparison table · flip default to hybrid only if it beats dense overall AND on keyword queries

✓ Done

Persistent index

SQLite store + index.py. Per-channel cursors, text_hash edit detection, model namespacing, --reconcile for deletions. Query cost is now independent of corpus size.

Queued

Relevance threshold gate

search_slack still returns top-K regardless of match quality. Needs one gate per mode — cosine has an absolute scale, BM25 is corpus-relative, RRF carries no relevance signal — calibrated on a filled-in golden set.

Future

Thread-level indexing

Thread is the unit of meaning in Slack, not individual messages. Index parent + replies as one document — decisions live in replies, not parents.

Future

Cross-encoder reranking

Only if Phase 4 shows a remaining semantic gap after hybrid. A reranker without a measured gap is wasted latency.
